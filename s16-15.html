Fromkin · 翻墙原理

第十四章 攻防军备竞赛：一部简史

没有哪把梯子活过自己的时代

把前面十三章的内容按时间排一遍，你会得到一部简史。这部历史有个残酷的规律：几乎每一代翻墙技术，从风光无两到大面积失效，中间只隔几年；而每一代封锁手段，也从无往不利到被绕得千疮百孔，同样只隔几年。没有谁赢过"最终胜利"，只有谁适应得更快。

理解这段历史，比记住任何一个具体工具的名字都重要。因为工具都会死，而这部历史里攻防双方的学习方式不会变。读完它，下次再遇到"某神器横空出世"或"某技术彻底凉凉"的新闻，你心里都会有个谱：哦，又是一轮——而且多半不是最后一轮。

第一幕：明信片时代

最早的突破工具简单得可爱：网页代理、开放代理服务器、第一代商用 VPN 服务，不一而足。那时的流量大多不加密，或者只做最基础的处理，相当于寄明信片——内容写在明面上，谁经手谁能看。

封锁方的应对也符合那个年代朴素的技术水平：看域名而已。被禁的网站名单一张，DNS 污染抢答假答案，IP 黑名单照单封门。这套打法对明信片时代的工具几乎是降维打击：你的目的地写得明明白白，人家甚至不需要拆信，按地址扣下就行。

那时的网页代理用起来是这样的：你先打开一个代理网站，在它页面上的输入框里填入你真正想去的网址，网页内容就被它抓回来塞进自己的页面里递给你。在今天看来笨拙得可笑，但在那个网页还很轻、互动还很少的年代，它确实够用——而且它有一个日后被反复借用的思想内核：让审查方看到的请求目的地，和你实际要去的地方，不必是同一件事。后来的域前置、CDN 借道，本质上都是这个老念头的升级版。工具会过时，念头会投胎，这也是这部简史读来不全是坟场气息的原因：大多数"新发明"，都是老想法穿上了新协议的外衣。

这一幕留给后世的教训是原点性的：**在审查面前，明文等于自首**。从此以后，"加密"从可选项变成了入场券，所有后来者都建立在这个共识之上。

插叙：整段被封的 VPN 年代

在进入下一幕之前，要为第一批"正规军"留一段。VPN 协议家族比翻墙圈的工具老得多：OpenVPN 首个版本 2001 年就发布了，作者 James Yonan；更早的 PPTP 是 1990 年代末的东西，后来因安全缺陷被淘汰，连微软这样的出身厂商都不再推荐。它们生在没有强审查的网络里，设计目标是给企业员工开一条回公司的安全通道——大方、标准、不遮不掩。

这份"不遮掩"到了强审查环境里成了致命伤。标准协议的握手特征是写进公开文档的，检测方照着文档就能编制识别规则：某个端口、某种握手节奏一出现，整段 IP 就被掐掉。商业 VPN 在开阔网络里是好产品，进了这片考场却常常连考场门都进不去。这段历史给后来的所有开发者上了一课：**在审查环境下，合规、标准、公开，恰恰是最容易被针对的三个属性**。翻墙工具的整个技术路线，就是从这一课开始拐弯的——从"做得对"转向"装得像"。后面还会登场的 WireGuard（2016 年首次公开、2020 年并入 Linux 内核主线）也带着同样的基因矛盾：它快、它优雅、它代码极简，但它的握手安安静静、特征鲜明——那是第十章讲过的故事，也是它需要 AmneziaWG 这类变装术的原因。

第二幕：轻骑兵的时代

2012 年，中国开发者 clowwindy 发布了开源工具 Shadowsocks，圈子里简称它 SS。它没有走"大而全"的路子，反其道而行：只做最核心的一件事——把流量加密后转发出去，设计极简，速度飞快，部署在自己的小服务器上几分钟就能跑起来。它"看起来随便"的气质在一开始甚至被当作优点：不起眼，不张扬。

Shadowsocks 的历史意义，不止于一个工具。它证明了"个人小服务器加轻量代理"这条路的成立，直接催生了后来的"机场"形态：有人批量维护服务器和线路，把连接能力做成订阅卖给普通人，翻墙从此从技术爱好者的手艺，变成了普通人能买到的服务。本书第十一章讲的整个机场经济学，都是这一幕结的果。

2015 年，作者迫于压力删除代码库并停止维护，社区随即接棒继续开发——这个细节本身就是一种隐喻：当一项技术的使用者足够多，它就不再属于任何个人，生杀予夺也就不再系于一人之身。

封锁方的回应姗姗来迟，但分量十足：深度包检测开始盯上这类"全加密、没头没尾"的流量特征，主动探测开始伪装成普通用户去敲可疑服务器的门。Shadowsocks 的黄金时代就此慢慢落幕。它的死因值得记住：不是加密被破解了——加密至今没被攻破——而是"一团没有特征的加密数据"这件事本身，成了最大的特征。

第三幕：躲进 HTTPS 的时代

突破方从上一幕的死因里读出了新思路：既然"不像任何正常东西"会暴露，那就索性**装成最正常的东西**。彼时互联网上最大的正常流量是什么？是 HTTPS——全世界的网站都在用它加密，银行、电商、邮箱，全在里面。躲进 HTTPS，就等于躲进人群。

这一幕的开场其实比 Trojan 们更早。2015 年出现的 V2Ray 项目及其 VMess 协议，是承前启后的一代：它在 Shadowsocks 的教训上往前走了几步，给流量加上了更完整的加密与身份校验，还搞出了一整套可扩展的"平台"，让各种传输方式都能插进来用。在很长一段时间里，它是圈子里的事实标准。但 VMess 的流量仍有自己可辨认的体态，随着检测方把它的特征摸透，它的黄金期也就到头了。2020 年，Xray 从 V2Ray 分叉出来，正是为了换一条更彻底的路线——这次不在旧协议上修补，而是从设计上把"像不像真正的 TLS 流量"当作第一性原理。这一分叉本身就是攻防史的缩影：当旧路线的特征已被学透，换代比修补更划算。

这一时期的代表作各有巧思。Trojan 的办法是让自己真的运行在一个正经的 HTTPS 网站后面：真域名、真证书，你直接去敲它的门，它表现得和普通网站没有两样，只有报对暗号的数据才会被转进代理通道。VLESS 则走轻量路线，它做了一个当时看起来反直觉的设计——自己不再叠加一层加密，而是把加密完全托付给外层的 TLS：既然 TLS 已经把通道锁好了，里面何必再穿一层盔甲，减掉反而更快、更像原生 HTTPS。配套的 uTLS 技术更进一步，连 TLS 握手时客户端露出的"笔迹"——那些参数的排列组合——都照着主流浏览器一笔一笔模仿，因为检测方已经学会了凭笔迹认人。

封锁方的进化同步跟上：SNI 阻断按握手里明文的域名掐线；TLS 指纹识别比对笔迹；对"全加密随机流量"的熵值检测则专门招呼那些还不懂得伪装的老实人。道高一尺，魔高一丈，这句话在这一幕里是双向成立的——两边都在以月为单位迭代，梯子的保鲜期被压缩得越来越短。

第四幕：借壳上市与新大陆

到了最近这一幕，突破方的手法又翻新了两路。

一路叫"借壳"。2023 年公开的 Reality 是代表：它连证书都不用自己办，而是直接借用某个真实大网站的 TLS 握手。审查方若来探测一台 Reality 服务器，看到的握手过程与访问那个大网站一模一样，证书都是真的——因为那一瞬间，它确实在和大网站的握手材料打交道。想封它，就要先想想误伤真网站的代价。

另一路叫"新大陆"。QUIC 协议由 Google 提出，2021 年被 IETF 正式发布为 RFC 9000，基于它的 HTTP/3 把全球网页流量的一大块搬到了 UDP 之上。UDP 这片地形对审查方相对陌生，而新协议又迅速被主流浏览器和大厂采纳，混在里面的代理流量有了全新的掩护。Hysteria 一类协议正是踩着这片新大陆长出来的：用激进的方式抢带宽，再把自己装扮成 HTTP/3 的模样。与此同时，老牌的 WireGuard 也在变装求生——AmneziaWG 给它加上垃圾包、填充和包头改造，专治 DPI 的识别；而 Cloudflare 的 WARP（2019 年推出）及其后基于 HTTP/3 的 MASQUE（RFC 9484 于 2023 年发布），则把"借大厂通道"做成了普通人的日常选项。

把这四幕连起来看，每一步的因果都清清楚楚：封锁学会看地址，流量就学会加密；学会认特征，流量就学会伪装；学会验指纹，流量就学会连笔迹都临摹；学会封协议的地盘，流量就搬去新协议的地盘。这不是谁比谁聪明的故事，而是谁的学习回路转得更快的故事。

一张时间线，把四幕串起来

为了看得更清楚，把散在各幕的年份拎出来排一次队。1990 年代末，金盾工程启动，国家网络边界上的审查与过滤体系自此有了依托，坊间所说的防火长城是其执行审查的系统通称。2001 年，OpenVPN 发布，传统 VPN 的全盛期开启。2012 年，Shadowsocks 发布；2015 年，V2Ray 项目出现、同年 Shadowsocks 原作者删库，社区接棒。2016 年，WireGuard 首次公开；2018 年前后，域前置被云厂商联手关闭。2019 年，Cloudflare 推出 WARP。2020 年是密集的一年：WireGuard 并入 Linux 5.6 内核，Xray 从 V2Ray 分叉并推出 VLESS。2021 年，QUIC 定稿为 RFC 9000。2023 年，REALITY 公开，MASQUE 定稿为 RFC 9484。

把这条线看久了会发现一个节奏：审查侧的大升级（深度检测成熟、主动探测普及）与突破侧的代际更替（伪装化、新大陆）总是前后脚出现，间隔大约三到五年。这个节奏不是巧合——它就是双方学习、研发、部署各自所需的时间。换句话说，这场竞赛的"回合时长"是由工程规律决定的，不由任何一方的意愿决定。理解了这个节奏，你对"最近怎么突然严了"的体感就有了出处：不是哪天谁拍了桌子，而是一套酝酿了几年的新系统恰好部署到位。

封锁的经济学

讲历史如果只讲技术，就漏了决定胜负的另一半：钱和代价。

先看封锁方的账本。它要在国家级的流量洪流里实时识别和拦截目标，设备、算力、人力都是天文数字的投入。更要命的是误伤的账：云计算时代，一个 IP 背后可能同时站着几百个毫不相干的网站和服务，下手重了，断的可能是正常外贸企业的邮件、可能是医院的远程系统、可能是自家机构的海外服务。每一次大规模误伤，都是要有人出来收拾的社会成本。

由此引出了公开讨论中经常出现的一个判断：理性的封锁追求的从来不是"百分之百封死"——那在技术上近乎不可能、在经济上更是灾难——而是**提高突破的成本与门槛**，让翻墙停留在"少数人费点劲能做到"，而不是"所有人随手就能做到"。一堵墙的成功，不在于它从没被人翻过，而在于它让大多数人觉得翻过去太麻烦。这话听着有些反直觉，却能解释很多现象：为什么有些缝年年都在、也没人真去堵死，为什么封锁强度总是在某些时段陡然收紧又慢慢回落——它调的从来不是"有或无"，而是"难与易"。

封锁方还有一本难念的账：规模。全量检测意味着每一条跨境连接都要被过一遍筛子，而跨境流量年年在涨，筛子的处理能力必须跟着涨；这还不算加密流量占比越来越高之后，"能看懂的流量"越来越少、单位识别成本水涨船高。于是现实中的系统不得不大量使用抽样、分级和阈值：不是每条连接都深查，而是先用便宜的方法圈出可疑的，再对可疑的下重手。你在日常使用中偶尔会感到"同一个节点，昨天好好的、今天连不上、过两天又好了"，有一部分就来自这种分级处理的波动——你的流量在不同日子里，被筛子分到了不同的格子里。

再看突破方的账本。开发新协议、维护节点、被封了换 IP、跟识别算法赛跑，同样烧钱烧人。商业化让这笔账有人买单（机场模式），也带来了新的脆弱性（第十五章会讲商家本身的风险）。开源社区则靠志愿者的时间和声望在运转——它的好处是杀不死，坏处是迭代全看核心维护者的精力。

攻防双方其实都被同一条经济学规律支配：**边际成本**。封锁方让突破难度再提高一成，需要的投入越来越多；突破方让伪装再逼真一分，研发和运维的负担也在加重。均衡点就在两条成本曲线的交点附近来回移动。你感受到的"最近严了""最近松了"，多半就是这个交点在动。

第三种角色：站在场边记账的研究者

这部简史还有个容易被漏掉的角色：公开学术界。加拿大的公民实验室（Citizen Lab）等研究机构多年以来系统地测量和记录各国审查系统的工作方式——DNS 污染怎么注入、主动探测怎么发问、哪些协议在哪一年被针对——许多已是论文和报告里的公开知识。本书的许多机制描述，源头就是这类公开研究。

研究者的存在，对攻防双方都是约束。对封锁方，它意味着手段很难真正保密：一套新部署的识别系统，被测量、被发表，只是时间问题；对突破方，它提供的实测数据是改版的依据，没有这套"公共情报"，开发者只能凭用户反馈盲人摸象。有趣的是，双方的工程师显然都在读同一批论文——这大概是这场没有硝烟的竞赛里最文明的一幕。

对普通读者的实际意义是：当你想判断"某工具是不是真的凉了"时，与其看自媒体标题，不如看有没有严肃的实测研究或项目方的技术复盘跟进。前者卖的是情绪，后者记录的是事实。这部简史之所以能被写出来，靠的正是这个公开记录的传统。

下一幕（分析推演）

下一幕的剧本，两边都已经写在了公开的研究里，这里只做标注清楚的推演。

可以推演的是：检测一方会越来越倚重机器学习，不再靠人写死的特征规则，而是让模型从海量流量里自己学会"什么长得像代理"；突破一方的回应，则是让流量的生成过程本身"拟态化"——用模型生成与正常应用难以区分的流量节奏和包长分布（分析推演）。攻防会从"规则对规则"升级为"模型对模型"，迭代速度被进一步压缩。

同样是分析推演：最终决定均衡位置的，可能不是某一方的技术上限，而是生态——哪边能调动更多的开发者、更多的商业投入、更多的真实用户流量作掩护。加密数学早已不是瓶颈，瓶颈在成本与规模（分析推演）。

但有一点不必推演，它是这部简史已经证明过的：一代技术从横空出世到“人尽皆知”，就是它寿命开始倒计时的时刻。所以看到任何"永久可用"的宣传，你都可以会心一笑——这部历史里，还没有出现过例外。

回望这四幕，还有一件事值得普通读者带走：攻防双方其实共享着同一个技术世界。TLS、QUIC 这些被用来伪装的协议，本是为全网的安全和加速而生的；DPI、流量分析这些被用来识别的技术，在企业的网络管理里也是正经工具。技术本身没有立场，让它成为"墙"或"梯子"的，是部署它的位置和目的。这也是为什么这场竞赛永远不会以某项技术的胜负告终——同一口锅里，盛什么菜的都有。下一章，我们要从这场竞赛里抽身出来，回到你自己的位置上：当你把流量托付给一条通道时，你究竟押上了什么。
