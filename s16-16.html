Fromkin · 翻墙原理

第十五章 安全、风险与边界

先问一句：你把什么交出去了

前面十四章，我们一直在讲通道怎么建、怎么绕、怎么快、怎么稳。这一章把问题倒过来：当你连上任何一条通道的那一刻，你究竟把什么东西交到了别人手里？

很多人用梯子时的心态是"我藏起来了"。但从网络结构上看，翻墙并不是让你消失，而是让你换了一条路走——而且这条路，是别人修的、别人守着收费站的。你的数据要从对方的服务器上过一遍手，这个事实不因你付没付费而改变。所以这一章只讲一件事：**信任**。理解了信任的边界，你才能用得明白、用得心安。

举个最日常的画面。你在旅途中连上一个来路不明的免费节点，顺手登了自己的主邮箱回了封信，又刷了下银行卡余额——整个过程页面都是 HTTPS，看起来固若金汤。可就在同一段时间里，这台节点的运营者在后台能看到：某个真实 IP，在几点几分访问了某银行、某邮箱，流量节奏如何。你也许永远不会知道这一幕发生过，运营者也许什么坏事都没做——但"也许"两个字，就是这一章要替你消除的东西。安全的用法不是指望每个陌生人都善良，而是让善良与否变得不重要。

总原则：节点即信任

把全章压缩成一句话，就是：你信任一个节点到什么程度，你的安全就到什么程度。反过来说也成立：你对一条通路的信任，也应当有明确的来历和限度，而不是来自广告。

这不是危言耸听，而是这项技术的结构本身决定的。你的客户端把数据打包送给节点，节点拆包、替你取数据、再打包送回。中间这一拆一装，就发生在别人的机器上。这台机器是谁的、记不记日志、出问题时跑不跑路，全在你的视野之外。你选节点时真正做的决策，不是"选了哪项技术"，而是"把这段路的知情权交给了谁"。

还要先分清"不安全"的三个层次，免得把不同的病开错药方。第一层是**技术层面的不安全**：流量没加密、明文裸奔，这可以用协议解决，加密用对了，这一层就关掉了。第二层是**运营者层面的不安全**：通道的经手人是否可信，这一层没有纯技术解，你只能靠选择、分散和缩短信任期来管理。第三层是**环境层面的不安全**：你所在法域的规则、服务的经营状态、商家明天还在不在，这一层靠的是常识和克制。本章接下来的内容，就是沿这三层依次展开——需要提醒的是，大多数人栽的跟头在第二、三层，而他们却总在第一层上反复加固，方向从一开始就错了。

下面就把这个"知情权"拆开，看看到底包括哪些东西。

运营者能看到什么，又看不到什么

先说看不到的，这部分由加密保证，相对让人安心：当你访问的是 HTTPS 网站时，你和网站之间的正文内容——账号密码、消息正文、表单里填的东西——被 TLS 端到端加密。节点在中间只能搬运一堆解不开的密文。它知道有数据在过，但不知道数据的正文写了什么。这是第六章那套"锁与钥匙"给你的保护，它对机场、对自建节点的朋友、对任何中间人一视同仁。

再说能看到的，这部分叫元数据，往往被低估：

第一，**你的真实 IP 地址**。节点要给你回数据，就必然知道你是谁、在哪儿上线。这是所有代理模式的共性，藏不住。

第二，**你连接的时间和流量大小**。几点连的、用了多久、跑了多少流量，这些在服务器一侧就是日常运维数据，想不记录都难——计费和排障都要用它。

第三，**你访问的目标**。节点替你敲哪个网站的门，它自然知道收件地址。更细一点说，在传统 TLS 下，握手里有你请求的目标服务器信息；你访问了哪家银行、哪个论坛、哪种服务，这个层面的行踪在节点眼里是清楚的。正文看不到，"你去过哪里"却看得到。

这三样合起来的画像价值，不要小看。知道一个人每天在什么时间、访问哪些类型的服务、流量呈现什么节奏，哪怕一个字的正文都没有，也足以勾勒出相当清晰的生活轮廓。所以"节点看不到我的内容"这句话只对了一半：内容安全，不等于行踪安全。

还有一类情况要单独提醒：当你访问的是老式的明文 HTTP 网站时，连"正文加密"这层保护都没有了，数据在节点面前是摊开的，节点甚至可以篡改页面内容再递给你。如今这类网站已不多，但一旦碰上，心里要有数：这时候不是"节点能不能看"的问题，而是路过的任何一站都能看。

免费节点的风险清单

把上一节的原理套到免费节点上，结论自然就出来了。免费节点的问题从来不是"慢"——慢只是最表面的缺点。它真正的问题是：你不知道运营者是谁，更不知道他图什么。

服务器和带宽都要花钱。一台节点免费给你用，它的成本必然在别处找补：可能是拿它做实验收集数据，可能是引流卖别的产品，也可能就是一台被攻陷后被顺手架起来的机器，或者干脆是钓鱼用的蜜罐。你无法分辨，也无从追责。现实一点列一张清单：

- **日志风险**：你的连接元数据（去了哪里、几点去的）被完整记录，与你无关时它是垃圾，与你有关时它就是档案。

- **明文劫持风险**：访问残留的 HTTP 网站时，页面可能被插入广告甚至恶意内容，这不是假设，是这类节点最常见的变现手法。

- **稳定性风险**：免费节点的生命周期以天计，今天能用明天消失是常态，它消失时不会给你任何通知。

- **连带风险**：同一个免费节点被无数人共用，其中任何人的行为惹来的封锁和标记，都会连累到从这个出口出去的你——比如某些网站对"名声不好的出口 IP"是直接拒绝服务的。

所以免费节点的定位，书里从头到尾只有一句：**只做浏览，不做登录**。查资料、看视频、读新闻，它足够；登录你的主邮箱、银行、政务账号，不行。这不是洁癖，是按它能提供的信任等级，给它安排配得上的工作。

付了钱，也不是进了保险箱

转到付费服务，风险的性质变了，但没有消失。

商业服务的好处在于它是一门实名生意：有品牌、有口碑压力、要靠续费活着，因此作恶的动机小得多，服务的连续性也强得多。但你要清醒地记得两点。其一，元数据的可见性不因付费而改变——前面列的那三样，付费节点照样看得见，你买到的是"对方更可信"，不是"对方看不见"。其二，商家本身成了新的风险点：它掌握着你的账号、你的支付记录、你的全部连接元数据；它若被入侵、被收购、或者经营者自己动了歪心思，风险敞口反而比免费节点更集中。

对商家的尽职调查，普通用户能做的其实有限，无非是看它运营了多少年、口碑如何、跑路时你的损失有多大——这也是为什么本书一再回到那条购买纪律：周期越短，押在对方身上的筹码越少。这不是不信任某一家，而是对"任何一家都可能出事"这一现实的基本尊重。

关于"日志"与那些无法验证的承诺

商家风险里藏得最深的一项，是日志。这里的日志不是你客户端里那份给你看的病历，而是服务器一侧对你连接行为的记录：几点、连了多久、去了哪里、用了多少流量。前面说过，其中一部分（计费、排障所需）是运营的刚需，不记录反而没法做生意；问题在于刚需之外的部分记多少、留多久、给谁看，用户完全无从知晓。

市面上不少服务会把"不记录日志"作为核心卖点。你需要明白这句话的成色：日志记在商家的服务器上，删没删、记没记，外人没有任何技术手段可以验证，它本质上是一句**只能靠信誉背书的承诺**，而不是一项可以验收的指标。这并不是说宣称者一定在说谎，而是说，把你的安全建立在别人一句无法验证的承诺之上，本身就是脆弱的。正确的姿势是反过来：默认任何通道都在记录它技术上能记录的一切，然后按这个假设去安排你的使用方式——哪些账号可以走、哪些内容可以过。这样安排之下，商家记不记日志，就从"性命攸关"降级成了"锦上添花"。

同样的逻辑适用于一切你无法亲自验证的安全宣传。凡是只能靠对方自说自话的指标，都要在心里打一个问号；凡是能用结构解决的问题——比如不让重要账号经过任何第三方通道——都优先用结构解决。这是把安全从"信人"切换到"靠制度"的关键一跃，也是本章想让你带走的最重要的方法论。

机场账号安全：把账号当成"不重要账号"来经营

既然付费账号本身成了风险点，就有必要单独讲讲怎么经营它。原则一句话：**把机场账号当成一个和你真实生活弱关联的"不重要账号"来经营**，万一它出事，火烧不到你本人。

第一，**注册邮箱不要用主邮箱**。你的主邮箱往往绑着银行、政务、各种实名服务，它在任何一个数据库里和别的信息拼起来，都能拼出你这个人。给机场注册单独准备一个不承载重要关系的邮箱，让这个账号在数据层面从一开始就和你保持距离。同理，在机场填的任何资料，都是"能少填就少填"。

第二，**密码必须独立**。不要用你任何重要账号的密码，也不要用它们的变体。理由是攻防史上最常见的连环车祸：A 网站的密码库泄露，攻击者拿着邮箱加密码的组合去 B、C、D 网站挨个试——密码复用一次，处处都是你家大门。机场这类服务的后台安全水平参差不齐，把它当作"迟早会泄露"来防，是最稳妥的假设。为它单独设一个只用在这里的密码，泄露也只烂这一口锅。

第三，**订阅链接当密码管**。第十一章已经讲过它就是你的账号钥匙：谁拿到它就能冒用你的账号、消耗你的流量、挤占你的设备名额，风控异常还可能连累你的账号被封。保管纪律和密码完全一致：只存在于自己的设备，不发给别人，不出现在公开截图里。若怀疑已经泄露，正确动作是去机场后台重置订阅链接（多数面板提供这个功能），让旧链接作废、生成一把新钥匙——就像怀疑密码泄露时先改密码，而不是继续观望。

把这三条做到，你在机场这一侧的风险敞口就收窄到了极限：账号里没有你的真实身份信息，密码不牵连其他账号，钥匙不出自家门。剩下的是商家层面的风险，那个只能靠选商家和缩短付费周期来对冲，不在你个人能控制的范围之内。

自建节点：把运营者换成自己，然后呢

顺着信任这条线走到底，自然会得出"最可信的是自己建的"这个结论。这话大体没错，但值得把账算细，因为自建不是把信任问题消灭了，而是把它**搬家**了。

你自己租一台云服务器搭节点，运营者确实变成了你自己：日志记什么你说了算，没人会拿你的元数据去变现，账号安全一侧也清白。但这台机器终究是租来的——云厂商能看见这台机器的存在、它的流量规模与大致的通信对象，这是任何租用关系都免不了的房东视角。再者，机器的安全从此全压在你自己肩上：系统不打补丁、密钥保管不当、配置写错，任何一项疏漏都等于把大门敞着，而这次没有商家客服替你兜底。最后，独享 IP 是一把双刃剑：它干净、只属于你，可也正因为它只指向你一个人，它与你之间的对应关系比共享出口清晰得多。

所以自建的准确定位是：**信任成本最低、维护成本最高**的一种选择。它适合愿意为"经手人只有自己"付出运维精力的人，而不适合把"安全"理解成"装好就再也不用管"的人。三种路线——免费、付费、自建——在这一章的坐标系里排开，其实就是一道信任与精力的交换题，没有标准答案，只有合不合你的账。

法律的边界：只陈述公开的事实

最后谈边界。这一节的写法先说在前面：只陈述公开的法规事实，不提供任何规避建议；每个人身处哪个法域、做什么用途，最终要由自己对自己的行为负责。

在我国的公开法规框架里，与本书主题直接相关的是这样几条事实。《网络安全法》是网络空间治理的基础性法律。工信部 2017 年发布《关于清理规范互联网网络接入服务市场的通知》，其中明确：未经批准，不得自行建立或租用专线（含虚拟专用网络）开展跨境经营活动。这是针对"经营行为"的规范口径。与此同时，合规通道是客观存在的：企业出于跨境办公等正当需要，可以依法租用合规的国际专线与相关服务，走的是备案与审批的路子。也就是说，法规区分了"依法合规的跨境联网"与"未经批准的经营性搭建"，前者一直有路，后者一直在被清理。普通读者需要建立的概念仅此而已：这类工具所处的法律环境不是真空，它的边界由你所在地的法规与你的具体用途共同决定。

放眼看，各国的态度差异很大：有的国家把 VPN 当作再普通不过的商业工具，有的则从严管制。这种差异背后是各自的网络治理逻辑，本书不做价值评判，只提醒一个常识——当你身处异国时，适用的规则跟着你的所在地走，不要拿惯常的经验去套另一个法域。

还有一点属于常识范围：法规是会修订的，执法口径也会随形势调整。本书成稿时陈述的，是写作时点上公开可查的文本；真到了要为自己的某个具体行为拿主意的时候，唯一可靠的动作是去查官方发布的现行文本，或者咨询专业人士，而不是拿任何一本科普书当法律意见。这不是推脱，是这类问题本来的严肃程度。

给你的数字生活排个座次

把这一章的原则落成日常习惯，最实用的办法是给你的账号排一个座次，然后让"座次"自动决定每个账号能走什么样的路。

最高一档是**命门账号**：主邮箱、银行与支付、政务服务。它们丢了，你的数字身份就丢了大半。这类账号只配走你完全控制的路——直连，或者你自己名下的节点——不配出现在任何第三方通道里，哪怕是口碑最好的付费服务。

中间一档是**日常账号**：社交、购物、内容平台。它们有价值，但丢了大多能找回、能止损。这一档可以走你付费且信任的通道，但对免费节点仍然免谈。

最低一档是**一次性账号**：为了看个页面随手注册的东西、薅完即弃的服务。它们和你的真实身份本来就没有连接，走哪条路都无所谓，免费节点伺候它们正合适。

这套座次不需要写下来贴在墙上，它只是一个在登录前过一遍脑子的动作："这个账号，是哪一档？现在这条路，配得上它吗？"三秒钟的自问，能挡掉绝大多数翻车。而它背后的方法论，和本章开头那句话是同一个：安全不是把每条路都修到最安全，而是让每样东西都走与它相称的路。

使用伦理与一条安全底线

抛开法规，还有一层是普通人的自我修养问题，本书的态度很明确，也写在这里作为全书的价值立场：

不利用通道去做伤害他人的事——不诈骗、不传播恶意程序、不侵犯他人的隐私与财产，这不是技术问题，是做人的底线。获取信息、学术研究、正常的工作与学习联通，是这类技术在全世界最广泛、最正当的用途；一个人手里的工具干净与否，不取决于工具，取决于握着它的手。

而安全底线，值得在合上书之前再重复一遍，因为它比所有协议都好记：**重要的账号，只走你完全信任的路**。主邮箱、银行、政务——这三样是你数字生活的命门。它们要么走你自己搭建、自己控制的节点，要么干脆直连。免费的路、来历不明的路、刚认识的商家，再快再便宜，都不配经手它们。安全感从来不是某个软件发给你的证书，而是你清楚地知道：自己的每一份数据，此刻正经过谁的手，又为什么可以放心。把这句话记住，这本书关于安全的一章，就算没有白写。
