Fromkin · 人工智能时代的AI基础设施

第十三章 应用层：给Agent看的网页、被Agent操作的App

这一章要讲全书最要紧的一个判断。先从一个你看不见的事实说起：此刻，全球约13.9亿个网站主机名背后（Netcraft《Web Server Survey》2025年12月调查口径，分布在约2.92亿个域名之下），每一秒都有天文数字的访问在发生。问题是，这些访问者里，有多少是人？Cloudflare Radar发布的《2025年度回顾》给了一个值得记住的数字：按其自家网络口径统计，2025年全年，网页（HTML）请求中只有43.5%来自真人，其余一半以上是各类机器程序——搜索引擎爬虫、监测程序、自动化脚本，以及这一两年飞速增长的AI爬虫。其中，专门为AI抓取内容的爬虫（不含谷歌的Googlebot）占4.2%，而Googlebot一个就占4.5%——它一边为搜索建立索引，一边为AI训练取材，一个爬虫的流量，超过了其余所有AI爬虫的总和。而且这还是2025年的数字，AI爬虫的增速远高于其他类别。换句话说，互联网的第一大读者已经不是人，而是机器。这个变化，是本章一切讨论的起点。

把机器读者拆开看，大致有三代。第一代是搜索引擎爬虫，为"被人搜到"而读——它读完网页、建好索引，等人来查。第二代是AI训练爬虫，为"喂大模型"而读——它读的是全网的语料，读完便沉淀进模型的权重里。第三代是这两年才冒头的"行动型"抓取：用户向Agent提一个问题，Agent当场去读相关的网页，读完立刻组织答案——据Cloudflare《2025年度回顾》披露，这类由用户提问触发的抓取，2025年一年里增长了超过15倍。三代爬虫叠在一起，意味着网页要同时应付三种读法：被索引、被学习、被实时征用。过去写网页只需讨好第一种读者，如今三种都要照顾到。

过去三十年，网页的设计哲学是彻底"以人为本"的：大图要抢眼，按钮要醒目，广告要塞进视线必经之路，内容要拆成许多页，好让人多停留一会儿、多点上几次。这套哲学服务的是人的眼睛和人的注意力。可当第一大读者换成了机器，问题就完全变了：机器不看排版，它读结构；它不被耸动的标题吸引，它要的是字段对齐、语义明确、接口稳定。一个写得花团锦簇的网页，在AI爬虫眼里可能是一团解不开的乱麻；反过来，一个人看起来平平无奇的页面，如果数据标得清清楚楚，机器一读就懂、一用就准。于是这些年，行业里悄悄开始了一场"给机器修路"的运动。最典型的动作是robots.txt的进化——这个管"爬虫能不能进门"的老文件，正在被网站逐家改写，声明AI爬虫能不能读、能读多少；一批网站开始另外提供机器专用的说明书：把内容概要、接口清单整理成给模型看的文本文件，放在站点目录里等AI来取；结构化数据标记，也从"做了加分"变成"不做吃亏"。这些动作眼下还零零星星，但方向是一致的：网页开始同时准备两张面孔，一张给人看，一张给机器读。

这场"修路"运动里，也有拉锯的一面。对内容生产者来说，AI爬虫是一把双刃剑：它能带来新的读者和订单，也可能把内容读走之后，让用户再也不必点开原站——"读了你的书，却不进你的店"。于是2025年前后，网站与AI公司之间的摩擦明显多了起来：有的站把AI爬虫一律挡在门外，有的站与AI公司签下授权协议、按内容收费，还有网络基础设施厂商顺势推出了"按次收费"的工具——AI每读一次，站方就收一次钱，明码标价。这笔账最后会算成什么样子，今天还没有定论；但有一件事已经清楚：内容被机器阅读，正在从"免费的默认"变成"有价的选项"，这是互联网商业规则的一次深层改动。

把这件事做到"官方出手"份上的，是浏览器厂商自己。2026年11月10日，谷歌Chrome团队联合微软Edge、Mozilla Firefox与MDN团队，发布了一个名为Modern Web Guidance的技能包1.0版——它包含203篇用例指南，覆盖250个网页平台特性，内容不是写给人学的，而是专门喂给编程Agent的"工作手册"：教Agent怎样用现代方式写网页、怎样避开过时的老写法。据其官方评测，配上了这套指南的编程Agent，写网页任务的表现明显优于"裸跑"。这件事的象征意义很大：浏览器行业里最有话语权的几家，联手把"如何开发网页"的知识，整理成了机器消费的格式。它等于承认了一个新秩序——网页的作者越来越多是Agent，那么连"作者手册"，也要先写成Agent读得懂的样子。给人看的网页、给Agent用的手册、供Agent读的内容，三层同时转向，才是这场变革的完整图景。

这场修路运动，也在改写网页设计师的功课表。过去，一名网页设计师的核心手艺是视觉：布局、配色、动效；如今，岗位要求里悄悄多了一项"机器体验"——页面结构是否语义清楚，数据有没有机器可读的标注，接口文档是否完整，内容有没有标明出处与更新时间，以便机器判断可信度。已经有团队把"Agent能不能顺利读完我们的网站"，列成正式的测试项目，像测试页面在手机上能不能打开一样常规。设计对象的扩容——从"人"扩到"人与机器"——是这一轮变革里最具体、也最先落到每个从业者头上的变化。

顺着这个逻辑往下推，就能看到本章的核心判断。分析推演：接下来的几年里，网页大概率会分化出"双层结构"——上层仍然是给人看的视觉页面，图片、排版、氛围一样都不会少；下层则长出一套给机器读的"影子层"：还是这些内容，但组织成结构化的数据、可调用的接口、可问答的知识。评价一个网站好坏的标准，也会多出一项过去不存在的东西——机器可读性。谁家的商品参数标得最准、谁家的办事指南接口最稳、谁家的内容最容易被AI正确引用，谁就更容易成为Agent给出的答案。与之相连的是流量入口的改写：过去网站争的是搜索引擎的排名，今后争的是"成为Agent答案里的出处"——人不再逐个点开链接，而是听Agent转述结论，网页从"目的地"变成"原料库"。这不是说视觉网页会消亡，而是它的主角地位要让出来：先被机器读懂，才有机会被人看见。

举个离生活最近的例子。一件商品，在人的页面上是模特上身图和热情洋溢的文案；在机器的那一层，它应该是一份清清楚楚的档案：材质、尺寸、库存、价格、退换政策，一项一项标好。将来你让Agent"挑一双适合雨天通勤、四十二码、预算之内的鞋"时，它比的不是谁家的图修得好，而是谁家的档案全、准、更新及时。卖家的工作重心，也会从"装修店铺"慢慢挪向"维护档案"——这和上一章说的框架之争一样，又是同一场转向在另一个楼层的回响。

双层结构还会动摇一个更底层的东西：网页靠什么挣钱。过去三十年，免费网页的商业模式建立在一块基石上——人的注意力可以卖钱，广告按眼睛的数量计价。可当第一大读者换成了没有眼睛的机器，这套计价方式就悬空了：Agent不会看开屏广告，不会被弹窗吸引，它的"注意力"无法变现。网站们迟早要回答一个新问题：当读者主要是机器时，收入从哪里来？眼下能看到的几条路是：向机器收费（按调用计价）、向人卖服务（内容免费、办事收费），或者成为某个Agent生态里的"官方数据源"。哪条路走得通，要由市场慢慢试出来；但"靠广告养网页"的旧地基正在松动，已经是正在发生的事实。

再看应用这一侧，也就是App。过去十年，App的核心资产是界面和时长：图标要抢眼，开屏要留人，信息流要让你划不到底。但当操作App的主体从人换成Agent，这套资产的成色就会大打折扣。Agent办事不靠看屏幕、找按钮——那是过渡期的笨办法，慢、贵，还容易点错；它靠的是调用App对外开放的能力接口：查一班车、下一次单、约一个号，都是一次结构化的调用。因此这两年，行业里最热闹的动作之一，就是给"能力接口"定规矩：函数调用成了大模型与外部软件对话的通用格式，一批开放协议被陆续提出来，想把"Agent如何发现工具、如何获得授权、如何返回结果"做成全行业通用的插座标准。这些协议谁胜谁负尚未定局，但方向没有悬念：App的竞争，正在从"抢用户的手指"变成"抢Agent的调用"——谁的接口全、稳、快、说明写得清楚，谁就被排在工具箱的前排。App也随之换了物种：从站在台前招揽顾客的"店铺"，退成站在幕后提供能力的"后厨"与"仓库"，而Agent是那个跑堂的——客人只见跑堂，不必进后厨。

当然，从"人点界面"到"Agent调接口"，中间隔着一个漫长的过渡期。眼下大量存量App并没有现成的能力接口，Agent要操作它们，只能学人的样子：看懂截图、找到按钮、模拟点击——这就是所谓的"视觉操作"。它笨重却必要，因为它不需要App做任何改造，是给存量世界准备的一根拐杖。可以预见，这根拐杖会用上很多年，直到主流App把接口补齐。还有一个现成的中间形态值得点名：小程序。它本就是寄生在大App里的小应用，不用安装、即用即走——某种意义上，小程序提前演练了"应用插件化"的剧本：入口与流量归平台，功能退到后台按需唤起。Agent时代的App生态，很可能就是这个剧本的放大版，只不过坐在平台位置上的，换成了Agent。

还有一个绕不开的问题：授权。Agent替你读网页，问题不大；替你操作App，就要碰权限了。查余额可以自动，转账就得慎重；订外卖可以自动，动用医保账户就必须本人确认。行业里正在形成的共识是分级授权：低风险的事，Agent放手办；高风险的事，必须回到人这里点头——这正是上一章说的"规则式授权"在应用层的样子。配套的还有一样东西：日志。Agent动过的每一个接口、改过的每一项数据，都要留下可查的记录，出了问题能追溯、能撤销。没有这套授权与留痕机制，"被Agent操作的App"就只能停留在演示视频里，进不了真实生活。

软件的生产方式，也在被同一股力量改写。已经发生的事实是：主流编程工具普遍内置了AI编程能力，"写代码"这件事正在变成"人提需求、Agent写初稿、人审查修改"的协作流水线；Modern Web Guidance那样的"Agent手册"能够显著改变产出质量，说明行业已经认真地在为"机器作者"配齐教材和规范。当然，边界也要划清：Agent生成代码的速度远快于人类消化它的速度，自动改动的软件谁来测试、谁来担责、出了事故查谁的账——这些问题今天都没有现成答案。分析推演：可以预见，软件行业的重心会随之移动——从"怎么写代码"移到"怎么写规格、定边界、做验收"，测试、审计、权限管理这些过去被看作配角的工种，会变成AI时代软件工程的主角；而软件的形态也会变：不再是几年才大改一次的"成品"，而是由Agent按需求持续小步修改的"活物"，版本号的概念淡化，变更的日志与回退的能力变得比版本号更重要。

这场生产方式的变革里，还有一个值得注意的侧面：软件的"作者结构"变了。过去做一款像样的软件，起步就是一支团队；如今一个人带着Agent，就能把从前一个小团队的活儿干下来——产品、代码、文档、测试，一人成军。这类一人成军式的开发者这两年明显多了起来，他们做的产品未必大，却验证了一件大事：软件生产的最小单位，正在从"团队"缩小到"个人加Agent"。与此同时，开源社区里也出现了新烦恼：自动生成的代码提交多了起来，维护者不得不立下新规矩，要求贡献者说明哪些代码出自AI、经过了怎样的人工检验。生产越容易，守门越重要——这句话，可能是AI时代软件工程最朴素的一条规律。

最后谈存量。全世界那约13.9亿个站点和数以亿计的存量应用，不可能推倒重来，改造必然有先后。按成本和收益粗排，大致的顺序是这样的。第一批被改造的，是"说明书型"内容：产品文档、帮助中心、政务办事指南、商品参数——它们本来就结构分明，改成机器可读的成本最低，而一旦被Agent顺畅引用，回报立竿见影。第二批是交易型服务：订票、挂号、下单、缴费——把界面背后的能力做成标准接口，Agent就能代办，省下的是全社会的时间。第三批才是那些流程复杂、年代久远的老系统：它们像老城区的管网，只能一段一段地换。这个排序未必精确，但有一条规律是稳的：越是"信息型、标准化"的软件，越早完成机器化改造；越是"强交互、重情感"的体验，人亲自到场的成分保留得越久（分析推演）。老网站不会消失，它们会像老建筑加装电梯一样，逐个加装"机器通道"——人的门面照旧营业，机器的侧门悄然打开。

政务服务是最能说明问题的一块试验田。这些年各级政务平台把办事指南、材料清单、办理进度都搬上了网，结构之规整，在所有网站里数一数二；它们离"机器可办"其实只差最后一步：把指南背后的受理能力做成标准接口。届时，"帮老人办一笔社保认证""给新开的小店办齐一套登记手续"这类事，Agent就能按图索骥地跑完大半流程，人只在最后出面确认。办事指南天生就是写给"照着做"的读者的——过去这个读者是人，今后越来越多是先由机器读懂、再替人跑腿。这也是为什么，越是公共服务做得规范的地方，Agent的落地反而越快。

不妨设想一下这场改造完成之后的日常图景。早上，你的Agent替你规划出差：它读了铁路与航空公司的机器接口，比价、下单、选座，再把行程写进日历——整个过程里，没有任何一个网页是"打开给人看"的。你要退改签时，也不必对着复杂的页面到处找入口，只需说一句"把周三的车次往后挪一天"，剩下的事，由Agent与各家系统在机器层面直接对接完成。人在这个图景里没有消失，只是从"操作者"变成了"决策者"：定规则、做选择、负最后的责任。网页和App并没有死，它们只是退到了人眼看不见的地方，安静地当着原料和工具。

最后，也要给这场转向泼一点冷水。网页为机器优化，会带来一个新麻烦：既然被AI引用能带来流量，就必然有人专门生产"喂给AI看"的内容——堆砌关键词的老把戏，会换上语义作弊的新马甲；更麻烦的是，AI生成的内容正在大量灌入互联网，机器读到的"原料"里掺入了越来越多机器自己的产物，原创与转述、事实与编造的界限，在规模上变得空前模糊。下一章讲安全与可信时还会回到这个问题。这里先记住一个判断：机器可读只是入场券，能不能被信任，才是下一轮真正的胜负手。

回到全书的那张分层图：这一章讲的，正是塔尖那一层的变样。操作系统沉到地下做安全底座，Agent升到顶层做总调度，网页变成给Agent读的原料，App退成供Agent调用的能力——应用层没有消失，而是换了一副面孔。当"读者"和"用户"都不再主要是人，整个软件世界的评价标准、商业模式与设计美学，都会跟着改写。对普通读者来说，这一章不需要记住任何技术名词，只需记住一件事：你早已习以为常的每一次"打开""点击"和"搜索"，正在悄悄换一种发生方式——先经机器的手，再到你的眼前。只是别忘了，塔尖再热闹，也离不开塔身的支撑：Agent越是无孔不入，安全、可靠与成本的问题就越突出。这正是下一章的主题。
