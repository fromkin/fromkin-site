Fromkin · 翻墙原理

第二章 数据包的旅行：先补一点网络常识

点开一个视频的那一秒

还是那个场景：你点开一个视频。屏幕上转了半秒圈，画面出来了。就这半秒里，你的手机和大洋彼岸的一台服务器之间，已经完成了几十个来回的对话，搬运了成千上万个小包裹。

这一章不讲墙，也不讲梯子，只讲这场旅行本身的规则。为什么需要这一章？因为后面所有的攻防，都是在这套规则里做文章的：墙封的"IP"，是规则里的门牌号；污染的"DNS"，是规则里的问路环节；梯子伪装的"握手"，是规则里的接头动作。规则不懂，招式看再多也是看个热闹。放心，这一章只讲七八个概念，每个都用生活里的东西打比方，讲完你就有了读懂全书的地基。

一切都被切碎：数据包

网络传输的第一个事实，可能和你的直觉相反：你在网上发的任何东西——一条消息、一张照片、一段视频——都不会整件上路。它会被切成许多小块，每块装进一个叫"数据包"的信封，分别寄出，在终点再拼回原样。

为什么要切碎？想象一家快递公司只接整柜发货：一件家具要占满一辆卡车，路上堵一次，全车迟到；别的小件只能干等着。切成标准小件就不同了：每件走一条当时最通畅的路，丢了一件只需补寄那一件，所有人的包裹共享同一套分拣系统。互联网选的是后者。这带来一个贯穿全书的重要后果：你的数据不是"一条专线"流向目的地的，而是无数个各自上路的小包裹；审查也好、加速也好，针对的往往是一个一个的包裹，或者是包裹上写的字。

每个信封上都印着几样基本信息：从哪儿来（源地址）、到哪儿去（目的地址）、包裹里装的是什么类型的东西、这是第几件中的第几件。路上所有的设备，主要就是看这些印在信封外面的字来决定怎么处理它——这一点请记牢：信封外面的字，是给路上人看的；信封里面的内容，才是你的隐私。后面墙的很多手段，利用的正是"外面的字看得见"。

IP 地址：门牌号

包裹要寄到，得有地址。互联网的地址叫 IP 地址，长得像四串数字，比如 142.250.72.206。把它理解成门牌号就行：全网唯一，靠它定位一台机器。服务器有自己的门牌号，你的手机和电脑接入网络时，也会被运营商临时分一个门牌号，别人回信就寄到这里。

有两点要补充，不然容易和后面章节对不上。其一，你家的地址其实是"小区共用"的。你家路由器从运营商那里领到一个对外的门牌号，家里的手机、电脑、平板再用一组内部房号（通常长 192.168 开头）彼此区分。外面的信寄到小区门牌，再由路由器这个前台按房号分下去。这个"前台转交"的机制叫 NAT，它有个意想不到的好处：从外面看，你全家显示为同一个地址，分不清是哪台设备——很多判断"谁在上网"的麻烦都来自这里。

其二，门牌号是会变的、也是能买卖和整批划拨的。服务器搬家要换号，云厂商手里攥着大批地址随时分配。这意味着"按地址封锁"永远是在追赶变化，这是第四章封 IP 那一招的先天短板。

端口：门牌号后面的房间号

光有门牌号还不够。一台服务器像一栋大楼，里面同时提供很多种服务：网页、邮件、视频、游戏，各走各的门。包裹寄到楼下，还得写清送到哪个房间——这个房间号就是端口。

你平时其实见过它，只是没意识到。你访问普通网页，走的是 443 号房间（加密网页）或 80 号房间（不加密网页）；你用的各种软件，各自有默认的房间号。地址加上端口，才算把一件包裹的去向写全了：某栋楼，某号房。

这个概念小，但用处大。后面你会看到：有些拦截是冲着房间号去的——某些房间太"专用"了，一看来往的包裹全进这个房间，就知道屋里在干什么；聪明的梯子则会去敲 443 那个最热闹、最不起眼的房门，混在每天数以亿计的正常网页包裹里。记住：地址决定你去哪栋楼，端口决定你敲哪扇门，这两样都写在信封外面，路上看得见。

路由：包裹是怎么一站站过去的

下一个问题：信封写好了，谁负责送？答案是：没有谁全程负责。互联网的送法是接力式的。

你的包裹先交到第一站（通常是运营商的一个节点设备，叫路由器），它看一眼目的地址，把包裹转给"离目的地更近"的下一站；下一站再看一眼，再往下转。如此十几跳、几十跳，最终送达。这就像古代驿站的接力，或者你查快递物流时看到的"已到达某分拣中心、已发出"——每个分拣中心只管把包裹往正确的方向推出去，不关心它的全程。

这套接力机制叫路由，它有两个对全书很重要的推论。

第一，路径不固定，也不对称。今天你的包裹从上海出海，明天可能从别的出口走；去程和回程完全可能不是同一条路。所以同一台服务器，你在不同城市、不同运营商、不同时段连，体验可能完全不同——不是玄学，是路径真的变了。

第二，每一站都只看信封。分拣中心不会拆包裹（也来不及拆），它按外面的地址决定下一站。这保证了互联网的速度，却也意味着：只要站在其中一站的位置上，把信封上的字都看一遍，就足以判断这包裹该放行还是扣留。第一章说审查站在咽喉位置上，道理就在这里：它不需要拆你的信，它只需要做一个手脚比较多的分拣中心。

DNS：先查电话簿

还剩最后一个日常环节。你上网时输入的从来不是门牌号，而是一个名字，比如一个视频网站的域名。机器只认数字地址，于是每次访问之前，必须先做一次翻译：把名字查成数字。

负责翻译的系统叫 DNS，你可以把它理解成全球电话簿。你的手机会先问运营商的电话簿服务（或者你设定的其他电话簿），电话簿查到号码，告诉你，你再按号码寄包裹。这个问路动作通常快到你毫无感觉，但它有两个决定性的特点，后面第三章整章都在讲它：第一，这一问在传统设计里是大声喊出来的——你问的名字，路上听得见；第二，你极度依赖这本电话簿的诚实，它给你什么号，你就往什么号寄，它指错了路，你一般没机会当场发现。

TCP 与 UDP：打电话，还是寄明信片

包裹一站站送过去，这是最底层的一层。再往上，通信双方还要约法一章：我们用什么方式组织这场对话。这里只讲两个最基本的规矩，名字先混个脸熟：TCP 和 UDP。

TCP 的方式像打电话。正式说话之前，先拨号、对暗号："听得到吗？""听得到，开始吧。"——这个接通仪式叫"握手"。通话过程中，每句话都要对方点头确认收到了；哪句没听清，立刻请对方重说一遍；结束时还有一句"没事我挂了"。这么做的代价是慢：光是接通就得先打两个来回，传输中还要不断确认。但换来的好处是可靠、有序：文件不会缺页，网页不会错位。我们访问网页、收发邮件、传文件，靠的基本都是它。

UDP 的方式像寄明信片，或者更准确地说，像朝着对面喊话。写好地址扔出去，不确认、不重发，对方收到多少算多少。丢了一张？无所谓，下一张马上就来。它粗糙，但快，而且省事。直播、语音通话、游戏对战喜欢用它：画面丢一两帧，你根本看不出来；可要是每丢一帧都停下来补，整个直播就没法看了。

这一节请你带走三个直觉。第一，TCP 的"接通仪式"是公开的、有固定腔调的，后面你会看到，墙能认出很多工具，靠的就是听它们接通时的腔调不对。第二，UDP 没有接通仪式，包裹说走就走，这个"不打电话、直接喊话"的脾气，后来被速度派的工具看中，成了新一代翻墙技术的重要地形（第十章）。第三，有的手段专门冲着 TCP 的规矩下手：既然它靠"确认"和"挂断"来维持秩序，那么伪造一张挂断条子，就能把通话搅黄——第四章马上就会讲到。

客户端与服务器：谁求谁办事

还剩一对概念，简单到容易被忽略：客户端和服务器。

服务器，是等着别人来找它办事的机器：网站、视频、聊天记录都存在它那里，全天开机，守着固定的地址。客户端，是主动上门求办事的一方：你手机上的每个应用都是客户端。你每点一下，客户端就向服务器递一个请求，服务器办完把结果送回来。我们这本书里反复出现的"节点"，本质上是一种特殊的服务器——它替你跑腿：你请求它，它再以自己的名义去请求真正的目的地。

有一个细节值得提前点破，因为它牵涉到隐私：普通的直连模式里，目的地的服务器能看见你的地址——它知道是谁在访问它。用了节点之后，目的地看到的是节点的地址，算是替你挡了一层；但反过来，节点能看见你要去哪里。世界上没有"谁都看不见"的通信，只有"换谁来看见"。这笔账，第十五章细算。

出口 IP：别人眼里，你"从哪里来"

顺着刚才的话头，再讲一个和地址有关、人人都会问到的问题：我的 IP 出口在哪里？

"出口 IP"不是一个新的技术名词，它就是：当你访问一个网站时，在那个网站眼里，你是从哪个地址来的。网站不认人，它只认地址——它把回信寄到这个地址，也据此判断你"身在何处"，该给你看哪个地区的内容、哪种语言、哪一套价格。

关键在于，这个地址会变，而且变的原因正是你有没有用梯子。

**没开任何代理的时候**，你的请求是从本地运营商的网络直接出去的。网站看到的，是你家宽带（或者你手机流量）对外的那个地址，它登记的位置就是你的所在地——你在南昌，它显示南昌。你的真实位置，在这一刻对每一个你访问的网站都是明牌。

**开了一台境外节点之后**，情形就完全不同了。你的请求先钻进加密隧道，到达那台节点服务器，再由它替你去敲网站的门。网站看到的来客地址，是节点的地址，不是你家的：你选了东京的节点，在网站眼里你就是一位"东京来客"；你换到美国节点，你的出口立刻"搬"去了美国。你的喜好、你点开的内容都还是你自己的，但你报给世界的地址，是你替身的地址。这正是"节点所在地"这个说法如此重要的原因——商家标注的日本、美国、新加坡，标的就是你出口 IP 显示的归属地。

这件事怎么自己验证？很简单，不需要任何工具：打开浏览器，搜"我的 IP"，排在前面的结果页会直接告诉你当前出口 IP 的地址和归属地。不开代理查一次，开着代理再查一次，归属地从你的城市变成节点所在的城市——这一变，就是整条梯子在工作的最直观证据。反过来，如果开了软件出口却没变，说明流量根本没从节点走，软件是"假连接"。这个自查办法，请记牢，它是后面判断一切通路是否真通的第一道关。

也要提醒一句分寸：出口变了，不等于你就"隐身"了。你藏起来的只是家庭地址这一项；你登录过的账号、你设备上的种种标识，网站各有各的认人办法。出口 IP 解决的是"从哪里来"这一个问题，别把它当成万能的隐身衣——第十五章还会回到这个话题。

串起来：一次完整的往返

把前面的概念串成一条线，你点开一个视频时，幕后大致是这样演的。

第一步，查电话簿。手机把视频网站的名字发给 DNS，换回一个数字地址。这一步快得像眨眼，但它发生在一切之先，谁在这一步做了手脚，后面全盘皆错。

第二步，打电话。手机按 TCP 的规矩和那个地址握手，三句暗号对上，通话建立。如果对方提供的是加密服务（如今绝大多数都是），紧接着还要在"电话"里再走一遍加密握手：互相验看证件、商量一把本次通话专用的暗号钥匙。第六章会把这遍握手放大了细讲——眼下你只需知道：内容从这时起是加密的，信封外面却还看得见地址、端口和一部分握手信息。

第三步，搬数据。视频被切片装包，一接力棒一接力棒地送过来，你的手机不断确认"收到"，缺的那包请对方重发。几秒钟内，先头部队就够你看上开头的画面了，后续的包一边播一边到。

第四步，收尾。你退出播放，双方礼貌地挂断。如果中途你换了网络、信号断了，通话就断在半道，软件会重新拨号——这就是你有时看到"重新连接中"的原因。

这个剧本里，请特别注意"电话"这个比喻的限度：真实的互联网没有一条实体的"线"把你们拴住，所谓的连接，只是双方各自记住"我们正在通话、各说到第几句了"的状态。任何一方把这个状态忘掉（或者被外人伪造一张"对方已挂断"的条子塞进来），通话立刻终止。这个看似抽象的细节，是第四章最重要的一招的全部原理，先存在心里。

顺便校准两个直觉：快，不只是带宽的事

很多人以为上网快慢只看"带宽够不够大"，其实还有一个同样重要的因素：距离与往返次数。

网络上的每一次对话都是问答式的：你说一句，对方回一句。信号在光纤里跑得再快，跨越半个地球也需要时间；再加上沿途每一站的排队和处理，一次问答的耗时有个下限，这就是老玩家说的"延迟"。服务器在本城，延迟可能只有几毫秒的感觉；在欧洲、美洲，往返一次就得零点几秒——数字不用记，记住量级带来的体感就行：网页要来回问答几十次才能拼齐，距离每多一分，卡顿就多一分。这解释了两个日常现象：为什么同一条梯子，连日本节点通常比连美国节点跟手；为什么有的工具费尽心思也要减少握手来回（第十章的速度派，干的就是这件事）。

带宽管的是"一次能并排走多少包裹"，延迟管的是"一个包裹一趟要走多久"。下载大文件看带宽，打游戏、看直播、刷网页，延迟的影响往往更大。卖家宣传里只喊"千兆带宽"不谈线路走向的，你就要多留个心眼——高速公路有十条车道，但修的方向不对，照样到不了你要去的地方。

用新概念，回看三个老故障

地基打完，立刻就能派上用场。拿三个你肯定遇到过的故障练一练，你会发现它们不再是不可理喻的"网络不好"，而是发生在这条链条的某一个具体位置上。

**故障一：软件显示"已连接"，网页却刷不出来。** 这往往是两个环节对不上：连接软件和节点之间那通"电话"打通了，但查电话簿的环节还在走老路，问出来的地址是错的，或者第一个数据包根本出不了本地网络。"已连接"三个字的含义，比大多数人以为的要窄得多——它通常只说明客户端到节点这一段通了，不代表整条链路都通。这也是为什么老手排障的第一反应是换个网站、换个应用试试：先分清是哪一段的事。

**故障二：在家里连得上，在公司就连不上（或者反过来）。** 路径变了。公司的网络可能有自己的出口规则和地址过滤，家里的路由器可能开了某种"智能加速"，两边的电话簿也不是同一本。同一台手机、同一个软件，在不同的网络里走的是两条完全不同的路，一条通、一条不通，毫不奇怪。很多人在这种时候去重装软件，其实软件从头到尾没变，变的是路。

**故障三：文字消息能收发，图片死活加载不出来。** 消息走的是长连接的小包通道，图片却是新开的下载请求，要重新查电话簿、重新握手、重新走一遍全程。链条里某一个环节只掐"新建的连接"或者只污染特定名字的查询，就会造成这种"半通不通"的怪象。能分清"已经在传的"和"新发起的"是一对完全不同的待遇，你离看懂故障又近了一步。

你发现没有，这三个故障的分析里，一个新名词都没用，全是这一章的地址、端口、电话簿、打电话。原理的威力不在高深，而在复用：为数不多的几个机制，排列组合起来，就是你日常遇到的大部分现象。

这一章的地基清单

最后，把这一章的概念排成一张清单，建议你记住它们各自的比喻，往后全书都按这套比喻说话：数据包是快递件，切碎了分别寄、在终点拼装；IP 地址是门牌号，你家是全小区共用一个对外门牌、内部分房号的格局；端口是门牌号下面的房间号，写明了包裹送到楼里哪个房间；路由是接力式的分拣，每一站只看信封、只管下一站；DNS 是电话簿，你上网前先把名字查成号码，而且这一问是喊出来的；TCP 是打电话，先接通、再确认、可靠但慢半拍；UDP 是寄明信片，快、随意、丢了不补；服务器是守着地址等生意的，客户端是上门求办事的，节点则是一种替你跑腿的特殊服务器。

还有两句话值得写在清单边上。第一，信封外面的字——地址、端口、名字——是给路上人看的，这决定了封锁方在不解密的情况下能做多少文章。第二，所谓"连接"只是一种双方记住的状态，谁能伪造状态、谁就能掐断通话，这决定了突破方为什么总要把自己的状态藏得严严实实。

地基到此。下一章开始，我们回到墙那边，看它的第一招：既然每次上网都要先大声问路，那么在问路这个环节上做手脚，会发生什么？
